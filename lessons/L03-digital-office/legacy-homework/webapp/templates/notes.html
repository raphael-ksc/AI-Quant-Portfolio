第三節課學習筆記：打造數字化辦公室

這節課在做什麼

這節課的主題是「基礎設施打造」，目標是把量化交易的開發環境從零建立起來， 分成兩大部分：一是 AI 輔助程式設計工具（Cursor、Trae、Claude Code、Codex） 與 Python 開發環境的建置；二是量化交易軟體與數據源的接軌， 課程原始教材以中國大陸的 QMT／miniQMT 為主，示範如何抓取日線、分鐘線、 財務數據，並在最後銜接到「多因子選股」的作業主題。

我做了什麼

因為我是台灣居民，無法使用 QMT，所以整堂課的重點變成「把 QMT 的邏輯 改寫成我實際能用的工具」。具體完成的事情包括：

  • 確認並開通 Moomoo（新加坡版）帳戶的 OpenAPI 使用權限
  • 下載安裝 moomoo OpenD 閘道程式，並成功登入連線
  • 安裝 moomoo-api Python 套件，驗證 import moomoo as ft 可正常運作
  • 釐清行情權限的關鍵限制：新加坡、日本、澳洲市場的行情數據 目前並非 Moomoo/Futu OpenAPI 支援範圍，僅港股與美股可用
  • 為作業選定三檔標的：Palantir（PLTR，美股）、IREN（原以為是澳股， 查證後確認其實是純美股掛牌）、必和必拓（BHP，改用 yfinance 抓取 澳交所 BHP.AX 版本）
  • 設計一套「雙資料源」的資料抓取架構：Moomoo API 負責美股， yfinance 負責澳股，並統一整理成同一種資料格式
  • 把資料抓取邏輯包裝成一個本機網頁小工具，可以按按鈕即時抓取 K 線圖與財務數據

整體流程

  1. 釐清自己的身分與券商限制（非中國大陸居民 → 排除 QMT）
  2. 確認替代方案（老師建議：Futu Moomoo Algo）
  3. 開通交易帳戶、完成合規問卷、下載安裝 OpenD 閘道程式
  4. 安裝對應的 Python SDK，驗證連線成功
  5. 檢查實際的行情權限範圍，調整選股標的以符合權限現況
  6. 設計資料抓取架構（分資料源模組、統一格式層、風險檢查）
  7. 把架構包裝成可互動的網頁工具，方便重複使用與展示成果

學到了什麼

  • 工具選擇要先確認自己的合法使用範圍：不能因為課程教材用什麼 就照抄，需要先確認自己的身分、地區、券商限制，再回頭調整整個技術架構。
  • 「帳戶開通了」不代表「API 權限就有」：交易帳戶、合規問卷、 行情權限是三個不同層次的關卡，缺一不可。
  • 不要憑直覺判斷一檔股票屬於哪個市場：IREN 雖然是澳洲公司、 總部在雪梨，但實際只在美股掛牌，這種「公司起源地」與「實際交易市場」 不一致的情況，在做多市場策略時必須逐一查證，不能用常識猜測。
  • 資料源的架構要為「可替換」而設計：把不同資料源包裝成獨立模組， 未來換資料源只需要換一個檔案，不用重寫整套邏輯。
  • 幣別是容易被忽略的風險點：PLTR/IREN 是美元計價， BHP 是澳幣計價，混在一起比較會產生誤導，必須在資料架構中明確標註。

Lesson 3 Learning Notes: Building the Digital Office

What this lesson covered

This lesson focused on setting up the infrastructure for quantitative trading from scratch, across two areas: AI-assisted coding tools (Cursor, Trae, Claude Code and Codex) alongside a Python development environment; and connecting quant trading software to a data source. The original course materials centre on QMT/miniQMT, which are mainland Chinese platforms, demonstrating how to retrieve daily bars, minute bars and financial data, leading into the homework topic of multi-factor stock selection.

What I did

As a Taiwan resident, I am unable to use QMT, so the core of this lesson became translating the QMT-based logic into tools I can actually use. Specifically, I:

  • Confirmed and activated OpenAPI access on my Moomoo (Singapore) account
  • Downloaded and installed the moomoo OpenD gateway, and connected successfully
  • Installed the moomoo-api Python package and verified import moomoo as ft works
  • Identified a key limitation: Singapore, Japanese and Australian market quotes are not currently supported by the Moomoo/Futu OpenAPI — only Hong Kong and US markets are available
  • Selected three tickers for the homework: Palantir (PLTR, US-listed), IREN (initially assumed to be Australian, but verified to be solely Nasdaq-listed), and BHP Group (switched to yfinance to retrieve the ASX-listed BHP.AX line, quoted in AUD)
  • Designed a dual-source data pipeline: Moomoo API for US equities, yfinance for the Australian listing, unified into a single schema
  • Wrapped the retrieval logic into a local web dashboard with a button that fetches candlestick charts and financial data on demand

Overall workflow

  1. Clarified my residency and brokerage constraints (not a mainland China resident, so QMT was ruled out)
  2. Confirmed an alternative (recommended by the instructor: Futu Moomoo Algo)
  3. Opened a trading account, completed the compliance questionnaire, and installed the OpenD gateway
  4. Installed the matching Python SDK and verified the connection
  5. Checked the actual scope of my quote permissions and adjusted the chosen tickers accordingly
  6. Designed the data retrieval architecture (source-specific modules, a unified schema layer, and a risk checklist)
  7. Wrapped the architecture into an interactive web tool for repeatable use and presentation

What I learnt

  • Confirm your legitimate scope of use before choosing tools — rather than copying whatever the course materials use, you need to check your residency, region and brokerage constraints first, then adapt the technical architecture accordingly.
  • An opened account doesn't automatically mean API access — the trading account, the compliance questionnaire and the quote permissions are three separate gates, and all three are required.
  • Don't assume a stock's market based on intuition — IREN is an Australian-founded, Sydney-headquartered company, yet it is solely listed on Nasdaq. This mismatch between a company's origin and its actual listing venue needs to be verified case by case when building a multi-market strategy, not assumed.
  • Design the data source layer to be swappable — wrapping each data source in its own module means switching providers later only requires changing one file, not rewriting the whole pipeline.
  • Currency is an easily overlooked risk — PLTR and IREN are USD-denominated while BHP is AUD-denominated; mixing them without labelling the currency would be misleading, so this must be made explicit in the data schema.
